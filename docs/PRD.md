# Mac Win Bridge PRD

## 1. 产品概述

Mac Win Bridge 是一套运行在 macOS 与 Windows 上的双端软件，用于解决桌面上同时摆放 MacBook 与 Windows 主机时，键盘、触控板和音频设备切换不便的问题。

用户可以在 MacBook 上通过快捷键或菜单栏开关，把 MacBook 的键盘和触控板临时切换为 Windows 主机的输入设备；也可以把 Windows 主机的系统声音实时转到 MacBook 扬声器播放。

本产品不以远程桌面为第一目标，不传输 Windows 屏幕画面。它更接近软件形态的 KVM + 网络音频桥接。

## 2. 背景与问题

典型使用场景：

- 用户桌面前方放置 MacBook，后方或侧边放置 Windows 主机、显示器、键盘和鼠标。
- 因 MacBook 占据身体正前方，Windows 键盘往往被迫放在 MacBook 后面，输入姿势不自然。
- 用户希望直接用 MacBook 自带键盘和触控板输入 Windows，而不是打开远程桌面窗口。
- 用户希望 Windows 声音可以从 MacBook 外放，减少桌面音频设备切换。

现有方案的问题：

- 远程桌面会改变使用模型，用户需要在 Mac 上看 Windows 画面，不符合“Windows 画面已经在独立显示器上”的场景。
- 硬件 KVM 需要额外设备和线材，对 MacBook 内置键盘/触控板支持有限。
- 鼠标键盘共享工具通常不处理 Windows 系统声音，也缺少针对“MacBook 内置输入设备接管 Windows”的模式设计。

## 3. 产品目标

### 3.1 用户目标

- 可以随时用 MacBook 键盘输入 Windows。
- 可以随时用 MacBook 触控板或外接鼠标控制 Windows。
- 可以灵活决定当前输入目标是 Mac 还是 Windows。
- 可以把 Windows 声音从 MacBook 播放。
- 每个能力可以独立开启或关闭。
- 配置一次后，日常使用尽量无感。

### 3.2 产品目标

- 第一版实现可用、稳定、低配置成本的输入与音频桥接。
- 明确区分“桥接输入”与“远程控制”，避免做成复杂远程桌面。
- 建立后续可扩展到虚拟 HID、剪贴板同步、文件拖拽、画面预览的架构。

### 3.3 非目标

MVP 不做以下能力：

- 不做 Windows 屏幕串流。
- 不做跨公网访问。
- 不做游戏级反作弊兼容承诺。
- 不做 Windows 锁屏界面输入承诺。
- 不做多台 Windows 同时控制。
- 不做手机或 iPad 客户端。

## 4. 目标用户

### 4.1 主要用户

同时使用 MacBook 与 Windows 台式机/迷你主机的个人用户，尤其是：

- 开发者
- 游戏玩家
- 设计、剪辑或办公用户
- 需要 MacBook + Windows 双系统工作流的人

### 4.2 用户画像

用户 A：开发者

- MacBook 用于日常沟通、文档、开发。
- Windows 主机用于特定 IDE、测试环境或硬件工具。
- 希望不移动手腕就能快速在两台设备之间输入。

用户 B：桌面游戏玩家

- Windows 主机连接外接显示器。
- MacBook 放在桌前用于聊天、攻略、音乐、轻量工作。
- 希望偶尔用 MacBook 键盘触控板控制 Windows 桌面，启动游戏或切换设置。

用户 C：轻办公双机用户

- Windows 主机连接公司系统或专用软件。
- MacBook 是主要个人设备。
- 不希望桌面放两套键鼠和音箱。

## 5. 核心使用场景

### 5.1 一键把 MacBook 键盘切到 Windows

用户正在 MacBook 上打字，看到 Windows 显示器上需要输入内容。用户按下快捷键，MacBook 键盘进入 Windows 模式，后续按键输入到 Windows。再次按快捷键，键盘回到 Mac。

### 5.2 按住快捷键临时输入 Windows

用户大部分时间仍然控制 Mac，只需要偶尔在 Windows 输入短文本。用户按住右 Option，期间键盘事件转发到 Windows；松开后自动回到 Mac。

### 5.3 MacBook 触控板控制 Windows 鼠标

用户开启触控板桥接，MacBook 触控板移动、点击、双指滚动会映射到 Windows 鼠标事件。用户可以独立关闭触控板桥接，只保留键盘桥接。

### 5.4 Windows 声音从 MacBook 外放

用户开启音频桥接后，Windows 系统输出音频通过局域网传到 MacBook 播放。用户可以在 Mac 端调节音量、静音或关闭音频桥接。

### 5.5 快速安全退出 Windows 模式

如果用户误进入 Windows 模式，需要始终有一个本地保留快捷键可以回到 Mac 模式，避免 Mac 输入被完全困住。

## 6. 产品形态

### 6.1 macOS 端：Mac Controller

形态：

- 菜单栏 App
- 首次启动引导授权
- 配对管理
- 状态面板
- 快捷键设置

核心职责：

- 捕获键盘、触控板和鼠标事件。
- 根据当前模式决定事件发给 macOS、Windows 或两者。
- 接收 Windows 音频流并播放。
- 展示连接状态、延迟、音频状态。

### 6.2 Windows 端：Windows Agent

形态：

- 托盘 App
- 可选开机自启
- 后台服务能力预留

核心职责：

- 与 Mac 端配对和建立加密连接。
- 接收输入事件并注入 Windows。
- 捕获 Windows 系统声音并传给 Mac。
- 展示连接状态、权限状态和日志。

## 7. 功能需求

### 7.1 设备发现与配对

优先级：P0

需求：

- Mac 与 Windows 在同一局域网内时，能够自动发现对方。
- 支持手动输入 IP 连接。
- 首次连接需要配对确认码。
- 配对后记住设备，下次自动连接。
- 支持取消配对。

验收标准：

- 两端启动后，Mac 端能发现 Windows Agent。
- 用户确认配对码后，连接成功。
- 重启两端后可以自动重连。

### 7.2 能力独立开关

优先级：P0

需求：

Mac 端提供独立开关：

- 键盘桥接
- 触控板/鼠标桥接
- 音频桥接
- 剪贴板同步，MVP 可先做预留开关或标记为 Coming Soon

验收标准：

- 关闭键盘桥接时，Windows 不接收 Mac 键盘输入。
- 关闭触控板/鼠标桥接时，Windows 不接收 Mac 指针输入。
- 关闭音频桥接时，Mac 不播放 Windows 声音。
- 各开关互不依赖，可以任意组合。

### 7.3 输入模式

优先级：P0

#### 7.3.1 Mac 模式

行为：

- MacBook 键盘、触控板正常控制 macOS。
- Windows 不接收输入事件。

#### 7.3.2 Windows 模式

行为：

- 开启的输入能力转发到 Windows。
- 对于已转发事件，Mac 端尽量阻止其继续进入 macOS。
- 保留一个本地逃生快捷键，用于立即回到 Mac 模式。

#### 7.3.3 临时穿透模式

行为：

- 默认仍控制 Mac。
- 用户按住指定修饰键或组合键时，输入临时转发到 Windows。
- 松开后自动回到 Mac。

验收标准：

- 用户可以通过快捷键在 Mac 模式和 Windows 模式之间切换。
- 用户可以设置一个按住生效的临时穿透快捷键。
- 逃生快捷键不被转发到 Windows。

### 7.4 键盘桥接

优先级：P0

需求：

- 支持普通字母、数字、符号输入。
- 支持功能键、方向键、删除、回车、Tab、Esc。
- 支持常用组合键，例如 Ctrl+C、Ctrl+V、Alt+Tab、Win 键映射。
- 支持用户配置 modifier 映射，例如 Command 映射为 Windows Ctrl 或 Windows 键。
- 支持中英文输入场景，MVP 优先处理按键级转发，不承诺输入法状态同步。

验收标准：

- 在 Windows 记事本中可以稳定输入英文、数字、符号。
- 在 Windows 常见软件中可以使用复制、粘贴、切换窗口等快捷键。
- Command、Option、Control 的映射可以配置。

### 7.5 触控板/鼠标桥接

优先级：P0

需求：

- 支持指针移动。
- 支持左键、右键、双击、拖拽。
- 支持双指滚动。
- 支持滚动方向配置。
- 支持速度和灵敏度配置。
- MVP 不承诺三指/四指系统手势完整映射。

验收标准：

- 用户可以用 MacBook 触控板移动 Windows 指针。
- 点击、右键、拖拽、滚动在 Windows 可用。
- 调整灵敏度后即时生效。

### 7.6 音频桥接

优先级：P0

需求：

- Windows Agent 捕获系统输出声音。
- Mac Controller 接收并播放。
- 支持音量调节、静音、开关。
- 支持低延迟模式与稳定模式。
- 网络抖动时不应导致 App 崩溃。

验收标准：

- Windows 播放音乐或视频时，MacBook 扬声器能听到声音。
- 开关音频桥接后，声音能在 2 秒内开始或停止。
- 局域网稳定情况下，音频延迟主观可接受。

### 7.7 状态展示

优先级：P1

需求：

- Mac 菜单栏显示当前连接状态。
- 状态面板展示：
  - 已连接设备
  - 当前输入模式
  - 键盘/触控板/音频开关状态
  - 当前网络延迟
  - 最近错误
- Windows 托盘展示：
  - 已连接 Mac
  - 输入注入状态
  - 音频采集状态

### 7.8 剪贴板同步

优先级：P2

需求：

- 支持文本剪贴板同步。
- 支持独立开关。
- 避免循环同步。

MVP 可不实现，但 UI 和协议可以预留。

## 8. 权限与系统限制

### 8.1 macOS 权限

需要：

- Accessibility，用于监听和控制输入事件。
- Input Monitoring，用于键盘事件捕获。
- Local Network，用于局域网发现和连接。
- Microphone 不应需要，因为本产品不采集 Mac 麦克风。

注意：

- 部分系统级快捷键可能无法完全拦截。
- 不同 macOS 版本对 event tap 行为可能存在差异。
- 必须提供清晰的权限引导和权限状态检测。

### 8.2 Windows 权限

需要：

- 普通桌面输入注入可优先使用 SendInput。
- 捕获系统音频可使用 WASAPI loopback。
- 若未来支持锁屏、UAC 或游戏场景，可能需要 Windows 服务或虚拟 HID 驱动。

注意：

- MVP 不承诺控制 UAC 安全桌面。
- MVP 不承诺绕过游戏或安全软件限制。

## 9. 技术方案建议

### 9.1 推荐架构

```text
Mac Controller
  - Menu Bar UI
  - Input Capture
  - Mode Manager
  - Audio Playback
  - Device Pairing
  - Network Transport

Windows Agent
  - Tray UI
  - Input Receiver
  - Windows Input Injection
  - WASAPI Audio Capture
  - Device Pairing
  - Network Transport
```

### 9.2 技术选型倾向

Mac 端：

- Swift / SwiftUI
- CoreGraphics event tap
- AVAudioEngine 或 CoreAudio
- Network.framework 或 QUIC/WebRTC 库

Windows 端：

- C#/.NET 或 Rust + Tauri
- Windows SendInput
- WASAPI loopback
- 托盘 UI

跨端协议：

- 控制消息走可靠通道。
- 高频输入事件可走低延迟通道。
- 音频流可使用 Opus 编码。
- 全连接加密，配对后使用设备密钥。

### 9.3 MVP 技术策略

- 输入先用 SendInput，不做虚拟 HID 驱动。
- 音频先用 WASAPI loopback + Opus。
- 传输先优先局域网直连。
- 配对先使用一次性验证码。
- 日志本地保存，方便排查。

## 10. 交互设计

### 10.1 Mac 菜单栏面板

面板内容：

- 当前设备：Windows 主机名
- 连接状态：已连接 / 连接中 / 未连接
- 输入模式：Mac / Windows / 临时穿透
- 开关：
  - Keyboard
  - Trackpad / Mouse
  - Audio
  - Clipboard
- 音量滑块
- 延迟显示
- 设置入口

### 10.2 快捷键默认值

建议默认：

- 切换 Mac / Windows 模式：Control + Option + Space
- 临时穿透：按住右 Option
- 紧急返回 Mac：连续按两次 Escape 或 Control + Option + Escape

默认值需要允许用户修改。

### 10.3 Windows 托盘面板

面板内容：

- 当前连接的 Mac
- 是否允许输入控制
- 是否发送系统音频
- 配对码展示
- 启动项设置
- 诊断日志入口

## 11. 安全与隐私

需求：

- 首次连接必须配对确认。
- 配对设备列表可查看和删除。
- 输入事件、音频流只能发送到已配对设备。
- 连接需要加密。
- 默认仅允许局域网。
- 不上传任何输入、音频或设备信息到云端。
- 日志不得记录完整键盘输入内容。

风险：

- 键盘事件属于敏感数据，不能持久化明文输入。
- 音频流可能包含会议或隐私内容，必须明确显示音频桥接状态。

## 12. 性能指标

MVP 目标：

- 输入端到端延迟：局域网内主观无明显卡顿，目标小于 30ms。
- 音频延迟：低延迟模式目标小于 100ms，稳定模式可更高。
- 自动重连：断线后 5 秒内尝试重连。
- CPU 占用：空闲低于 3%，正常输入与音频桥接低于 10%。
- 内存占用：单端常驻低于 200MB。

## 13. 兼容性

MVP 目标：

- macOS：优先支持 macOS 14 及以上。
- Windows：优先支持 Windows 10 22H2 与 Windows 11。
- 网络：同一局域网，支持 Wi-Fi 与有线网络。

暂不承诺：

- 公网 NAT 穿透。
- 企业网络复杂隔离环境。
- Windows 安全桌面、锁屏界面、反作弊游戏。

## 15. 验收用例

### 15.1 输入桥接

前置：

- Mac 与 Windows 在同一局域网。
- 两端已配对并连接。

步骤：

1. Mac 端开启键盘桥接。
2. 切换到 Windows 模式。
3. 在 Windows 打开记事本。
4. 用 MacBook 键盘输入英文、数字、符号。
5. 使用复制、粘贴、删除、回车、方向键。

预期：

- Windows 正确收到输入。
- Mac 当前输入框不应同时出现同样字符。
- 紧急返回快捷键可回到 Mac 模式。

### 15.2 触控板桥接

步骤：

1. Mac 端开启触控板/鼠标桥接。
2. 切换到 Windows 模式。
3. 移动触控板、点击、右键、拖拽、双指滚动。

预期：

- Windows 指针和滚动行为正常。
- 关闭触控板/鼠标桥接后，Windows 不再响应触控板。

### 15.3 音频桥接

步骤：

1. Mac 端开启音频桥接。
2. Windows 播放音频。
3. Mac 调整音量与静音。
4. 关闭音频桥接。

预期：

- MacBook 能播放 Windows 声音。
- 音量与静音生效。
- 关闭后声音停止。

### 15.4 断线重连

步骤：

1. 两端连接后断开 Wi-Fi。
2. 重新连接同一网络。

预期：

- App 显示断线状态。
- 网络恢复后自动重连或提供明显的重连入口。

## 16. 风险与待验证问题

### 16.1 Mac 输入拦截可靠性

风险：

- macOS 对键盘监听和事件吞掉有权限限制。
- 某些系统快捷键无法拦截。

验证：

- 先做最小 Swift event tap demo。
- 验证普通按键、modifier、功能键、触控板事件的捕获与阻断能力。

### 16.2 Windows 输入注入兼容性

风险：

- SendInput 在普通桌面软件中可用，但对管理员窗口、UAC、游戏可能有限制。

验证：

- 先覆盖记事本、浏览器、文件管理器、常见 IDE。
- 后续再评估虚拟 HID 驱动。

### 16.3 音频延迟

风险：

- Wi-Fi 抖动可能造成延迟、爆音或断续。

验证：

- 比较 PCM、Opus 低延迟编码、不同缓冲策略。
- 提供低延迟与稳定两档。

### 16.4 安全感与误操作

风险：

- 用户误进入 Windows 模式后，可能短时间无法控制 Mac。

验证：

- 强制保留逃生快捷键。
- 菜单栏状态必须明显。
- 切换模式时提供轻量提示。
